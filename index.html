极验第四代风格 · 滑动拼图验证

按官方 gcaptcha4.css（v1.9.7-0ad79a）的几何比例与配色逐项还原， 面板宽 340px，所有尺寸使用官方原始百分比，可等比缩放。 背景图与拼图块由 Canvas 现场生成，无任何外部图片依赖。

逐项对账。本地实现与官方 gcaptcha4.css 做了逐项 getComputedStyle 比对：阴影与外观 15 / 15 一致、动画 10 / 10 一致、 @keyframes 逐帧 9 组全部一致（其中 statusmove 为写法不同但等价）。 详见下方「官方对账」。
滑块尺寸可调。官方按钮是 80 × 50（占图片宽 26.83% × 16.77%），在 18px 轨道上偏大， 本项目默认收到 48 × 30（16% × 10%）—— 正好等于拼图块本体宽度， 复刻官方「切块与按钮等宽」的设计。要改尺寸覆盖 CSS 变量即可：
:root {
  --gt-btn-w: 16%;   /* 宽（相对图片宽度）*/
  --gt-btn-h: 10%;   /* 高 */
  --gt-arrow-w: 19px; --gt-arrow-h: 16px;
  --gt-track-h: 6%;   /* 轨道高 */
}
想完全还原官方：--gt-btn-w:26.83%; --gt-btn-h:16.77%，拼图块传 pieceSize: 80。
拼图块同样可调。官方拼图块边长 80px / 背景宽 300px = 26.67%， 占掉图片近 1/4 宽、40% 高，在 300 × 200 的图上很压。本项目默认收到 48px（16%）， 凹凸半径按 13/80 的比例跟着缩放，形状比例与官方完全一致。
GtCaptcha.init({
  el: '#captcha',
  pieceSize: 48   /* 拼图块边长（原图像素），建议 40 ~ 80 */
});
注意：拼图块 48px 恰好等于按钮宽度 16%（48px）—— 官方原本就让两者等宽 （切块 26.67% ≈ 按钮 26.83%），收小后这个关系仍然保持，拖动时手感一致。 若换成带凸起的形状（如默认的经典拼图），切块可见宽度会比按钮略宽 （凸起不占本体），想完全等宽就用 shape: 'wedge'。
成功收回动效。验证通过后：绿色提示条滑入、状态条与开合层描边转绿， 滑块按钮和拼图块都停在原位不动（官方就是如此 —— CSS 里没有任何规则 在成功时改 .geetest_btn 的位置，那些 success 动画都属于绑定手机号 和其他验证类型），→（延迟到 1000ms）整个面板收回：走官方 hideBox —— .gt-box-layer-btn 从铺满面板的尺寸缩回 260 × 50， 两条 6px 描边同时反向收线，且成功态下描边是绿色。详见下方「成功收回动画」。
按钮与拼图块在代码里是解耦的（_setBtn(x, keepPiece)）， 所以"只让其中一个动"是支持的，只是成功态按官方行为两者都不动。
失败换题。官方验证失败后会重新下发一道随机题（新背景 + 新缺口位置）， 切换动效是旧题 mvToLeft 向左滑出、新题 mvToCenter 从右滑入。 本项目对齐了这套流程：提示条 + 状态条转 #ff5d39 + 抖动 → 900ms 后换题。不想换题、只在原题上重试，传 renewOnFail: false。 详见下方「换题切换动画」。
深色主题与无动画。两档开关，都是 CSS 侧的实现，不用改结构。
GtCaptcha.init({ theme: 'dark' });  // 给 .gt-box 挂 .gt-dark
<html class="gt-no-animate">  // 手动全局关掉所有动画
此外组件已接上 @media (prefers-reduced-motion: reduce) —— 系统开了「减弱动态效果」时，开合、标题淡入、遮罩、换题横滑会自动全部关掉， 不需要额外配置。

切块形状（内置 12 种，可自己加）

缺口和切块用的是同一条 Canvas 路径，所以任何形状都能严丝合缝对上 —— 每个形状都把切块对正缺口验过，暗边一点都不露。
shape: 'jigsaw'       // 单个形状
shape: ['jigsaw', 'star', 'circle']  // 数组 = 每题随机取一个
怎么加自己的形状。形状表就是一个 { label, pad, path }：
GtCaptcha.registerShape('heart', {
  label: '爱心',
  // 形状相对 size×size 方框向外溢出的量。溢出多少就报多少，
  // 报少了缺口会压到图片边缘、切块会被画布裁掉。
  pad: function (size, tab) { return { l: 0, t: 0, r: 0, b: 0 }; },
  // 在 (x, y) 处画一个 size×size 的闭合路径，用 ctx 画什么都可以
  path: function (ctx, x, y, size, tab) {
    ctx.beginPath();
    ctx.moveTo(x + size / 2, y + size * 0.82);
    ctx.bezierCurveTo(x - size * 0.2, y + size * 0.5,
      x + size * 0.12, y - size * 0.16, x + size / 2, y + size * 0.24);
    ctx.bezierCurveTo(x + size * 0.88, y - size * 0.16,
      x + size * 1.2, y + size * 0.5, x + size / 2, y + size * 0.82);
    ctx.closePath();
  }
});
// 然后就能用了：GtCaptcha.init({ shape: 'heart' })
两条硬约束： ① path 必须是确定性的 —— 缺口和切块各调用一次， 中间不能有随机数，否则两者画出来不是同一个形状，缺口会露边； 想要随机形状，随机在「选形状」那一层（传数组），别在画路径那一层。 ② pad 要如实申报溢出量。
画圆角块不用手算贝塞尔。官方那两种圆角形状（wedge / arrow） 就是拿这个工具两行写出来的，它已导出：
// 顶点数组 + 圆角半径 → 一条带圆角的闭合路径
// 半径会自动收敛到相邻边长的一半以内，小形状也不会画崩
GtCaptcha.roundedPolygon(ctx, [[x + size / 2, y + size * 0.88],
                     [x, y],
                     [x + size, y]], size * 0.18);
所以加一个「圆角六边形」「圆角五角星」也就是把顶点列出来、给个半径的事。

成功收回动画（验证通过后面板收回）

官方是怎么做的。官方 .geetest_box_layer 里有个 260 × 50 的 .geetest_box_btn —— 尺寸正好等于触发按钮。开面板时 showBox 把它从 260 × 50 长到 100% × 100%，所以面板本质上是"从按钮长出来的"； .geetest_hideBox 就是 showBox 的反向，而且成功态下描边会变绿： .geetest_success .geetest_box_btn:before/:after { background: #39c522 }。
本项目的实现。不再自己算"朝按钮缩小的位移"，而是照抄官方的机制： .gt-box-layer-btn（260 × 50、border:1px solid #dfdfdf、 box-shadow:0 4px 10px rgba(0,0,0,.02)）用 gt-showBox / gt-hideBox 在 260×50 ↔ 100%×100% 之间长/缩， ::before 铺顶边横线（gt-lineRight）、 ::after 铺左边竖线（gt-lineUp），三者共用 .4s cubic-bezier(.65,0,.35,1)：
@keyframes gt-showBox  { to { width:100%; height:100%; } }
@keyframes gt-lineRight { 99% { border-radius:4px 4px 4px 0; }
                    to { width:100%; border-radius:4px 4px 0 0; } }
@keyframes gt-lineUp   { to { height:100%; } }
时序：绿色提示条与描边转绿 → 1000ms 后面板收回 → 动画结束才摘掉 gt-open（先动再消失，否则 display:none 会把动画掐断）。 主动关闭（点遮罩 / 按 ESC）走的是同一套动画。
不想让面板自动收回，传 closeOnSuccess: false，面板会留在原地展示结果。

换题切换动画（验证失败 / 点「换一题」）

官方是怎么做的。官方有两套动画专门管换题，名字很反直觉（mvToLeft 看着像"收回"，其实是横滑）：
.geetest_mvToLeft { animation: mvToLeft .6s cubic-bezier(.65,0,.35,1) forwards !important; }
.geetest_subitem  { animation: mvToCenter .6s cubic-bezier(.65,0,.35,1) .1s forwards; }
mvToLeft：scale(1) → scale(.95) 再 translate3d(-120%,0,0) 滑出画面；
mvToCenter：从 translate3d(120%,0,0) 滑入，70% 处回到原位并复原到 scale(1)。官方 .geetest_subitem 就是"一整个子题"（图 + 轨道 + 滑块）， 对应本项目的 .gt-slide。
一个必须一起抄的细节。mvToCenter 的 fill-mode 只有 forwards、没有 backwards，所以那 .1s 延迟期间套用不上任何关键帧值 —— 官方靠 .geetest_subitem 的基础样式 opacity:0 把它藏住。少抄这一条，新题会先在原位闪 0.1s 再瞬移到右侧滑入。
本项目把它写在状态类里，并在动画结束后摘掉类：.gt-mv-center 一残留， 动画被打断或遇到 animation:none 时整块内容就会消失。

官方对账（逐项 computed 值比对）

怎么比。同一页同时加载官方 gcaptcha4.css 与本地 gt-captcha.css， 给两套同义 DOM（带上正确的祖先链与状态类），用 getComputedStyle 逐项读 15 个属性； @keyframes 直接从 CSS 文本解析（file:// 下读 styleSheets[i].cssRules 会抛 SecurityError）。
切块投影。官方切块的投影没有 CSS，是烘焙在 PNG 里的。用 「实心掩码平移 → 高斯模糊 → ×不透明度」做模型，对 8 道官方题联合拟合 （拟合域取整幅画布全像素，不透明度用闭式解 Σ(m·t)/Σ(m²)）：
shadowBlur=9  offset(2,2)  rgba(0,0,0,.723)  →  全像素 RMSE 3.21 / 255
（并列候选：blur8 → 3.48  blur10 → 3.81  方框模糊 radius7 → 4.63）
官方直边实测剖面 108,93,74,57,42,30,21,14,10,8,5,3,2,1， 模型预测 106,91,78,63,50,38,27,19,13,8,4,2,0,0； 本地实测在 d≥2 时平均绝对误差 1.44 / 255。
唯一残留的 d=1 差 48/255 是官方切片无抗锯齿（边缘 alpha 40 → 255 一行直跳） 造成的，属渲染质量差异，不是参数偏差。

接入方式

<link rel="stylesheet" href="css/gt-captcha.css">
<script src="js/gt-captcha.js"></script>

// 1. 浮动式（居中弹窗 + 遮罩）
var captcha = GtCaptcha.init({
  el: '#captcha',              // 触发按钮挂载点
  product: 'float',          // 'float' 浮动式 | 'popup' 跟随弹出
  theme: 'light',           // 'light' | 'dark' 深色主题（给面板挂 .gt-dark）
  title: '请完成安全验证',
  brand: '俱乐部电竞助手',        // 品牌字，替代原 GEETEST 标志
  feedbackURL: 'https://www.7od.cn', // 反馈按钮跳转地址，传 '' 则不跳转
  pieceSize: 48,               // 拼图块边长（原图像素），官方 80，可调
  shape: 'jigsaw',             // 切块形状；传数组则每题随机（官方就是随机形状池）
  closeOnSuccess: true,         // 成功后自动收回面板；false 则留在原地展示结果
  renewOnFail: true,             // 失败后换一题（官方行为）；false 则留在原题重试
  onSuccess: function (res) {
    // res.lot_number 需要连同业务参数一起发给后端二次校验
    submitBtn.disabled = false;
  },
  onFail: function () { /* 失败 */ }
});

// 2. 主动调用
captcha.show();      // 打开面板
captcha.refresh();   // 换一题
captcha.setShape('star');  // 换切块形状（内部会换一题）
captcha.close();     // 关闭（带收回动画，动画结束才触发 onClose）
captcha.destroy();   // 销毁

// 3. 形状表：读内置形状 / 注册自己的
GtCaptcha.shapeNames();              // ['jigsaw','jigsaw-in', ...,'wedge','arrow']
GtCaptcha.shapes.circle.label;       // '圆形'
GtCaptcha.registerShape('heart', { pad: ..., path: ... });
GtCaptcha.roundedPolygon(ctx, pts, r);  // 画圆角多边形（wedge / arrow 就是用它写的）
这是纯前端的界面还原，校验在浏览器本地完成。生产环境必须把 lot_number 等参数交给服务端校验， 前端只负责采集行为轨迹 —— 否则任何滑块验证都可以被一行 JS 绕过。
